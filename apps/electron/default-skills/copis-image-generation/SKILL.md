# Copis 图片生成

当用户要求生成图片、插图、配图、海报、封面或头像时，使用 Copis 内置的
`generate_image` 能力。该能力由 Copis 后端选择图片模型并负责认证、计费和上传，
客户端不得直接调用供应商接口，也不得要求用户提供模型 API Key。调用采用异步任务：
提交后保存后端返回的 `task_id`，轮询任务状态到 `completed` 或 `failed`。

## 查询与恢复

- 用户提供 `task_id` 或希望取回之前的图片时，调用 `get_image_task({"task_id":"原任务 ID"})`。
- 不知道 ID 时，调用 `list_image_tasks({})` 查找当前账号最近的本地任务；已知会话可传 `session_id` 筛选。列表是本地快照，选定任务后再调用 `get_image_task`。
- 查询返回 `completed` 时展示工具返回的真实图片附件；返回 `queued` 或 `running` 时告知尚未完成，后续仍查询同一 ID。
- “等待取消或超时”表示客户端停止等待，不表示后台失败；从错误中保留 `task_id`，通过查询取回原任务，禁止再次调用 `generate_image` 代替恢复。
- Rust 将任务 ID、账号及会话归属、状态、图片 URL 和有效期保存到本地 SQLite。有效 URL 直接复用，过期 URL 由 Rust 向 model-request 刷新；不要自行拼接 URL 或修改数据库。
- 查询与展示不重新生成、不重新扣费。账号无权访问、任务失败或网络异常时，说明真实错误，不切换账号绕过权限。

## 调用规则

调用前将需求整理为清晰、可执行的提示词，依次包含主体、场景、动作、风格、构图、
光线、比例、尺寸，以及 `must_include` 和 `avoid`。除非用户明确要求图片文字，否则
要求画面不出现文字。`size` 可选，未提供时交给后端按当前模型配置决定。

只展示工具返回的真实图片附件，不编造 URL、本地路径或生成结果。成人、血腥、仇恨、
危险操作、自伤、隐私诱导和受版权保护角色或真实人物肖像请求应拒绝或改写为安全的
原创描述。

图片生成失败时原样说明后端返回的错误类别；认证、上游权限、超时和模型错误不得
统称为 MCP 或认证服务不可用。任务提交只允许执行一次，不得因查询失败自动重复提交。
