# AI 浏览器模拟鼠标设计

## 目标

当 AI 浏览器 Agent 通过 CDP 执行当前网页的点击、输入、选择、按键或滚动操作时，在内嵌网页上显示一个短暂的模拟鼠标指针，让用户能看到 Agent 当前作用的位置和动作状态。指针只存在于 Copis 内部网页页签，不移动操作系统真实鼠标，也不遮挡或拦截用户操作。

## 方案比较

### 方案 A：在网页 DOM 中注入指针（采用）

主进程使用已有的 `Runtime.evaluate`，在当前网页中创建一个 `position: fixed` 的指针节点。控制服务使用与 CDP 鼠标事件相同的页面视口坐标更新指针，再派发真实 CDP 输入事件。

优点是指针与网页坐标系一致，能够覆盖原生 `WebContentsView`，不需要新增 IPC 或渲染层浮层窗口。网页导航后节点自然销毁，辅助指针失败也不会阻断页面操作。

### 方案 B：在 Electron 主窗口渲染层绘制

由 React 根据主窗口状态绘制指针。

该方案无法可靠覆盖原生 `WebContentsView`，还需要处理页签位置、缩放、窗口移动和导航同步，坐标误差风险较高，不采用。

### 方案 C：移动操作系统真实鼠标

通过 Electron 或系统 API 移动真实鼠标。

这会干扰用户当前操作，突破网页内部控制边界，也无法稳定处理多页签，不采用。

## 交互行为

- `click`：指针移动到目标中心，显示按下状态，完成 `mousePressed`/`mouseReleased` 后短暂保留并自动隐藏。
- `type`、`select`、`press`：指针移动到目标中心并保持可见；输入或按键完成后短暂保留并自动隐藏。
- `scroll`：指针移动到当前视口中心，显示滚动状态，滚动完成后自动隐藏。
- `navigate`：导航前尽力移除指针；导航失败或页面被销毁不影响导航错误处理。
- 连续动作：新动作取消前一个隐藏定时器，复用同一个节点，避免页面中累积多个指针。
- 辅助视觉注入失败：记录调试日志但继续执行原本的 CDP 动作。

## 架构与数据流

1. `browser-page-control-service` 解析目标元素并获得页面视口坐标。
2. 控制服务通过 `Runtime.evaluate` 调用指针脚本，脚本创建或更新带 `data-copis-ai-browser-cursor` 标识的节点。
3. 控制服务按当前已有顺序派发 CDP `Input.dispatchMouseEvent`、键盘或滚动事件。
4. 指针脚本使用 `pointer-events: none`、固定定位和最高页面内层级，不能改变网页事件命中结果。
5. 指针状态只保存在当前网页 JS 上下文，不写入设置、会话 JSONL 或 Agent 上下文。

输入目标和点击目标统一返回目标中心坐标；坐标来自目标 `getBoundingClientRect()`，与 `Input.dispatchMouseEvent` 的坐标系保持一致。滚动没有目标引用时使用当前视口中心。

## 实现边界

- 新增纯函数或局部脚本生成器，集中生成指针的注入、移动、按下和隐藏脚本，禁止在各动作中复制脚本字符串。
- 指针的视觉样式使用网页内轻量 CSS，包含清晰的箭头/圆环、按下缩放反馈和短暂过渡；不引入图片、外部资源或新的依赖。
- 所有指针坐标必须经过有限数值校验并限制在页面视口范围内。
- 不把网页内容、元素文本或 selector 写入指针节点。
- 页面不支持脚本或 CDP 页面上下文已销毁时，视觉反馈降级，不改变授权和安全策略。

## 测试与验收

BDD 场景：

```text
Given Agent 已授权且观察到一个可点击元素
When Agent 点击该元素
Then 在派发 CDP 鼠标事件前注入指针移动状态
And 鼠标按下/释放期间指针显示动作状态
And 指针注入失败时点击仍完成

Given Agent 已授权且观察到一个可输入元素
When Agent 输入文本
Then 指针移动到输入框中心后再聚焦和输入

Given Agent 已授权
When Agent 滚动页面
Then 指针在当前视口中心显示滚动反馈并自动隐藏

Given 网页发生导航或 CDP 上下文销毁
When 下一次页面操作开始
Then 不复用旧页面节点，不阻断新页面操作
```

自动化验证覆盖：

- 指针脚本生成器的节点标识、坐标和 `pointer-events: none` 约束。
- 点击、输入、选择、按键和滚动的 CDP 命令顺序。
- 辅助注入命令失败时原始页面操作仍成功。
- `bun test` 定向测试、`bun run typecheck`、Electron 主进程和渲染进程构建、`git diff --check`。

Electron UI 的真实视觉效果由用户在实际应用窗口中确认，Agent 不使用截图或截图比对替代确认。
