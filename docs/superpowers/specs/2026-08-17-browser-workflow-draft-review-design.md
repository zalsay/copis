# Browser Workflow 草稿审核条设计

## 目标

精简 Browser Agent 面板中的 Workflow 草稿审核提示，让用户确认版本时聚焦于目标地址、步骤规模和审批操作，而不在提示条中重复展示操作细节。

## 范围

仅调整 `BrowserAgentPanel` 的 `awaiting_review` 展示和组件契约测试；不修改草稿内容、审批 IPC、Workflow 持久化或既有录制存储目录。

## 交互

- 草稿已加载时，标题显示为 `{draft.start.url}自动化流程草稿`。长 URL 在面板内截断显示，仍使用完整的 `draft.start.url` 作为内容来源。
- 标题右侧仅保留 `{draft.steps.length} 步`。不显示变量数、Origin 或各步骤明细。
- “允许该版本无人值守运行”在每次进入草稿审核时默认勾选；用户可在确认前取消勾选。
- 原生复选框的勾选色使用 `var(--ui-primary)`。
- “取消（不做更新）”调用现有拒绝草稿流程，不产生 Workflow 更新。
- “确认（更新为确认后版本）”调用现有审批流程，并传递当前无人值守开关的值，使草稿落盘为确认后的版本。

## 错误与状态

- 草稿加载中和操作进行中沿用现有状态与禁用逻辑。
- 审批或取消失败仍由现有 toast 提示；本次不改变错误文案与服务端行为。

## 验证

- 先更新 `BrowserAgentPanel.test.ts` 的源代码契约，覆盖标题、步骤数、无明细、默认开关、主题勾选色和两个操作文案。
- 先运行该测试观察预期失败，再最小化修改组件并复跑。
- 执行 Renderer 类型检查与构建。Electron 实际窗口中的最终视觉和交互仍需用户确认。
