# DSH 群聊协作 V1：分享码入群，共用群主的智能体

**状态：产品范围已确认；本文是设计，不代表已实现或上线。**

## 用户能做什么

A 创建共享群，选择一台自己的 Copis 设备和要共享的 DSH 智能体。A 为每个智能体明确选择发布给该群的资料；不选资料也可以只回答群里的问题。建群确认页列出智能体、资料范围、执行设备，并说明调用使用群主配置的模型及其额度。

B 用自己的 Copis 账号登录，输入分享码入群。普通消息以本人身份发送，不触发模型。B 显式 `@` 一个共享智能体后，全群看到是谁发起、哪个智能体在处理，以及最终回复或失败原因。B 不需要配置 A 的模型，也不会得到 A 的任何凭据。成员可离群；群主可移除成员、换码、停码、暂停或撤回智能体。

「群聊协作」直接显示共享群，不提供本地群入口或本地／共享切换。群目录、创建与加入操作统一放在工作区下方的原生侧栏分组；右侧不再显示第二列导航，收起分组不关闭会话。复用群详情、消息列表及输入框。不自动转换旧群，不上传本地聊天记录。共享群首版不展示尚未共享的本地看板、附件按钮或“完全访问”入口。

## 复用边界与职责

| 部分 | 第一版职责 |
|---|---|
| edu-api Chatroom V2 | 作为共享群的权威数据源：登录身份、房间、成员资格、分享码、消息序号、事件及调用记录。复用 4 位字母数字码、加入限流、换码、停码。分享码只用于入群；此后的每次访问均校验登录身份和有效成员关系。 |
| Copis 客户端 | 共享房间走现有登录身份与受限的主进程接口，不接受渲染层自报的用户 ID。群列表及本地缓存按账号和房间隔离；切换账号时取消旧订阅、清空界面。断线按游标补拉，按服务端消息 ID 去重。 |
| 群主设备上的 DSH | 用本地映射把房间公开的智能体 ID 对应到群主选定的智能体配置、资料版本和专用 DSH 会话。远端看不到本地路径、密钥或原生会话标识。群主退出客户端不影响其他人继续聊天。 |

**源码基线**：Copis `d2a19cf4`，ai-education `1620272a`（本地检视）。`backend/modules/edu-api/routes.go` 已注册 Chatroom V2 的房间、加入、消息、事件、WebSocket 和智能体管理接口；`services/chatroom_v2_executor.go` 有执行端绑定。Copis 的 `native/http-api-server/src/main.rs` 当前明确拒绝旧聊天室路由。接入时只引入本功能所需的已认证调用，不整段放开旧路由，不恢复 Pi Worker 或旧聊天室 UI。`DshGroupChatService.executeCreationStream` 的直接模型请求仍属于本地旧群，不能作为共享 DSH 执行端的替代品。生产端能力开关、连接方式和授权行为需要联调确认，不能由源码存在推定。

## 一次调用如何执行

1. 服务端先保存消息。无 `@` 不创建调用；首版只支持指定一个本群共享的智能体，多目标或 `@所有人` 不触发批量执行。
2. 服务端检查成员、智能体共享状态、群主设备在线状态及额度限制，生成唯一调用 ID，并绑定当前就绪的群主设备。成员不能自行指定执行设备、本地目录或会话 ID。
3. 群主设备领取后再次核对绑定及共享授权，以调用 ID 作为幂等键，向本群专用的 DSH 会话提交一次请求。不同房间、不同共享智能体不复用会话；不续接群主的私人会话。入队确认与执行完成是两个不同状态。
4. 回传仅限允许公开的状态、回答和错误摘要。服务端只接受绑定执行端的结果，同一调用最多发布一条最终回复。网络重连先查原调用状态，不能判断是否已执行时不盲目重跑。
5. 群主离线或智能体暂停时，显示不可用，不在后台积压待执行请求。执行中失联先显示中断；恢复连接时可核对既有结果，但不擅自重新执行。普通成员消息正常保存和同步。

## 资料、权限与费用

- 共享单位是**发给这个群的资料**，不是“给群成员一个只读工作区”。优先使用群主显式选定的文件快照；原目录新增文件不自动公开。更新资料需重新发布。不能向成员暴露本地目录浏览、路径读取或通用 DSH RPC。
- 在 DSH 会话和工具执行层限制输入来源与可用能力，不靠提示词防护。禁止修改群主工作区、运行终端、读取私人历史、调用未授权的技能/MCP 或私人浏览器；资料内容也不能改变权限。若当前运行时不能可靠执行该限制，智能体不得标记为“可共享”。
- 移除成员后，服务端拒绝该成员的新请求并停止其旧连接接收后续事件；停用分享码只阻止新加入，不踢出现有成员。撤回智能体或资料后不再接受基于旧授权的任务，丢弃撤权后到达的未发布结果并隔离含旧资料的会话。已发到群里的回答不承诺可以从成员处收回。
- 模型消耗归群主配置；建群时明确提示，提供按成员的调用频率限制、每群并发上限及暂停入口。只允许群主调整执行策略。首版不新增付费产品、不修改钻石或 VIP 逻辑。

## 开发顺序与放行条件

**第一步：先验证两条必要链路，不先改界面。** 在隔离测试环境用两个账号验证 edu-api 加入、成员鉴权、消息同步与移除后的实时撤权；在开发版 DSH RC2 验证独立会话提交、最小资料访问权限、取消和重复调用去重。先通过，再接现有群聊页面和设备执行端。若发现必须修改 edu-api 或 DSH 才能保证权限，记录缺口并单独评审，不能用直接模型调用或扩大权限绕过。

| 给定 | 操作 | 必须观察到 |
|---|---|---|
| A、B 为不同账号，在两台设备登录 | A 建群并分享；B 用码加入、发消息 | 两端为同一房间；显示 B 的真实身份；普通聊天不调用模型 |
| A 分享一个智能体和一份资料 | B 提问并显式 `@` 它，随后重连 | 仅 A 指定设备执行一次；两端看到同一个结果，无重复回复 |
| A 在两个群共享同一智能体 | B 询问另一群对话、未共享文件或要求写文件、执行命令 | 不泄露、不产生主机副作用；不能靠任何成员的文字放宽权限 |
| A 换码、移除 B 或撤回资料 | 分别用旧码、B 的既有连接、旧资料发起请求 | 三种撤销各自生效，撤回资料不得从后续会话上下文绕过 |
| A 离线 | B 普通发言后再 `@` 智能体，随后 A 上线 | 人能继续聊天；智能体提示离线；上线不补跑离线期间的指令 |
| 已有本地群，或账号切换 | 首次打开新版或改用另一账号 | 不上传旧群、不混入另一账号的共享群消息 |

验收只覆盖本功能链路；真实双账号双设备及 Electron 窗口交互单独验收，不用截图或单测代替。首版不做共享任务看板、Leader 自动派单、跨设备接管、群成员托管自己的智能体或成员远程操作主机。

## 首次实现记录（本地，未发布）

- **房间协议**：edu-api 增加 `TestDSHSharedRoomV1MemberRoundTrip`。两套独立登录会话经真实 HTTP 和 WebSocket 建房、入群和同步同一条消息；移除成员后拒绝读写，既有订阅收不到后续消息。使用临时 PostgreSQL、内存 Redis 和本地测试服务，不代表生产能力开关或两台设备已验收。
- **桌面入口下层**：共享群命令经现有 `dshGroupChat` preload → 受信主窗口 IPC → Working facade → 仅限内部令牌的 Rust 网关。只支持列群、建群、入群、读消息与普通文本发送，不转发任意路径、身份或模型参数。切换账号后丢弃旧响应。旧聊天室路由仍返回 404。
- **执行端组件**：在独立 Cordis 容器中运行已安装的 DSH RC2 AgentLoop；只注入群主已发布的文本快照，不加载私人 profile 和主机工具。以离线测试模型验证分群隔离、拒绝工具请求、有限模型步数、撤权取消，以及重复调用的结果复用；重新创建执行器遇到已领取的调用会拒绝重跑，等待核对服务端。未接入真实费用或上线设备注册。
- **复验**：在 Copis 仓库执行 `python3 scripts/verify-dsh-shared-room-v1.py --runtime-dir <已安装的RC2目录>/runtime`。需本机 Node、Bun、Go、Rust、PostgreSQL 命令行；可传 `--edu-api` 选择 edu-api 模块目录。脚本只运行此功能的用例并自动停止临时数据库。
- **尚未开放的产品路径**：既有群聊 UI 的共享群入口、桌面端实时订阅与游标恢复、群主发布资料和租约调度（包括暂停/撤回后的服务端终态处理）、真实账号及双设备验收。因此不能把独立的会话组件直接注册为在线执行端。

## 桌面接入进度（本地，未发布）

- 「群聊协作」独立显示在工作区列表下方，不参加「Copis 功能」的固定或展开。页面只显示共享群，沿用消息工作台、输入框与消息气泡；历史本地群数据不删除、不上传。
- 真人共享群已接入建群、分享码入群、查看房间、发送、历史翻页及按游标增量补读。窗口切换账号时销毁共享群状态；出站消息在未确认时保留草稿，同房间内重试相同文本复用消息 ID。Rust 只返回界面所需字段，不向渲染进程转发执行载荷。
- 当前桌面打开房间时通过已认证 HTTP 增量补读（常态约 3 秒），不是 WebSocket 推送；群主智能体状态取自 edu-api 的 `availability`。未接入群主设备授权发布、执行器租约或真实 `@` 派发；因此本阶段只能发送普通消息，不显示可调用的 `@` 操作。
- 自动验证覆盖侧栏几何位置、建群/入群/发消息交互、账号切换清理、状态读取与幂等重试；隔离服务测试覆盖两个登录会话的数据同步、游标读和撤权。正式账号、两台实际 Copis 窗口与线上环境未验收。
